在 fileOS 中一切皆文件，每个键各自合并，同时写入同一个键会变成并排的多个版本。所以本页所有做法背后只有一条原则：

**让合并的单位和人们修改的单位一致。** 互不相关的修改放进不同的键；必须合并的修改交给 CRDT。

这是一个经过验证的老办法：Maildir 一封邮件一个文件，几十年来一直是最好同步、最不容易损坏的邮件格式之一。

## 十条做法

1. **一条记录一个文件，用固定的 ID 命名。** 用 `/contacts/01J9X….cbor`，而不是一个大的 `contacts.json`。这样冲突只涉及一条记录，变化事件精确到记录，授权可以按前缀划分，同步也只传改动的部分。
2. **ID 用随机值，或按时间有序的随机值**（UUIDv7、ULID），或者内容的哈希。永远不要用递增的计数：两台离线设备会给出同一个号码。给人看的名字是字段，不是路径，这样改名只改一个字段，不移动任何东西。
3. **会被分别修改的字段：** 把记录保存为一个小的 CRDT 文档（Loro 的映射），或者把每个字段放进自己的键（`/contacts/<id>/name`）。只会被一个人整体修改的记录，用普通文件就可以。
4. **事件、动态、聊天和计数用 “每条记录一个文件” 的目录。** 每条记录是一个小文件，用按时间排序的 ID 加上作者命名，所以文件名永不重复，并按时间排序。记录之间永远不会冲突。当前的状态由所有记录计算出来（事件溯源）。计数器是一组 “+1” 文件，永远不要写成 `x = x + 1`，两台设备同时这样做会丢失更新。
5. **集合用目录里的键表示。** 相册里的照片是 `/albums/<相册>/items/<照片-id>`：有这个键就在，没有就不在。添加和移除是不同的键，所以可以合并。不要在一个文件里存一个 ID 数组。
6. **有序列表**在键里使用分数索引（`/playlist/<位置>-<id>`），新项目可以插在任意两项之间；项目经常被移动时，用 Loro 的可移动列表。
7. **节点会移动的树**不要放进路径。每个节点有一个 “父节点 ID” 字段。移动很频繁时（例如大纲），使用 Loro 的可移动树，它能处理会形成环的并发移动。
8. **大的二进制数据单独成为文件。** 记录里只保存它的路径或哈希。大文件会切成块，版本之间共享相同的块。永远不要把图片或视频放进记录里。
9. **查询和索引放进缓存文件，那里很适合用 SQLite。** 文件是真相：它们负责同步、合并、版本和授权。索引由文件生成，只在每个节点本地。App 可以在自己的缓存文件里放一个 SQLite 数据库，在收到变化事件时更新它，用 SQL 做查询。它丢了，就从文件重建。它从不同步，所以从不冲突。这样你既能用 SQL，又避开了 SQL 数据库无法合并的问题。
10. **格式要开放、自描述、带版本。** 有标准格式的地方就用标准格式：联系人用 vCard，日程用 iCalendar，笔记用带 front matter 的 Markdown，照片信息用 XMP 附属文件。这样数据比 App 活得更久，别的 App 也能读，CalDAV 和 CardDAV 适配器也能直接使用。你自己的格式（CBOR 或 JSON）要带 `schema` 版本，并且只增加新字段。读取时跳过不认识的字段；写入时原样保留它们，这样旧版本的 App 不会删掉新版本写的内容。

## 不要这样做

- **不要依赖合并无法保证的规则。** 尽量把它们设计掉：用 ID 代替唯一的名字，用集合代替有上限的计数。确实需要时，在合并钩子里检查，或者使用权威路径，但要很少用。
- **不要把共享方式不同的数据放进同一个文件。** 授权按路径前缀，一个文件不能只共享一半。私人笔记和与家人共享的笔记，要放在不同的前缀下，或者不同的空间里。
- **不要把临时状态放进需要保留的文件。** 光标位置、“正在输入”、“在线” 不是数据：它们作为**短消息**在在线的节点之间传递，从不保存（这个通道以后再做）。否则它们就是白白增长的数据。
- **不要过于频繁地写同一个键**，比如每按一次键写一次。频繁的修改放进 CRDT 文档（它会把操作压缩在一起），或者先在内存里攒一小会儿再写。

## 什么数据用什么结构

| 数据的形状             | 结构                         | 例子                   |
| ---------------------- | ---------------------------- | ---------------------- |
| 互相独立的记录         | 每条一个文件，用 ID 命名     | 联系人、书签、待办     |
| 会被多人同时修改的记录 | 每条一个小的 CRDT 文档       | 共享的任务卡片         |
| 只增加的事件           | “每条记录一个文件” 的目录    | 聊天、动态、日志、计数 |
| 集合                   | 目录里的键                   | 相册成员、标签         |
| 有序列表               | 分数索引的键，或可移动列表   | 播放列表、看板列       |
| 结构会变化的树         | 父节点字段，或可移动树       | 大纲                   |
| 富文本                 | 文本 CRDT，带历史            | 文档、笔记正文         |
| 大的二进制数据         | 单独的分块文件，加一条小记录 | 照片、视频             |
| 需要搜索的数据         | 缓存文件里的 SQLite 索引     | 搜索、筛选、统计       |
| 临时状态               | 短消息，不保存               | 光标、在线状态         |

## 例子

- **通讯录：** `/contacts/<id>.vcf`，每人一个 vCard 文件；分组是 `/contacts/groups/<组>/<id>` 下的键；用缓存文件里的 SQLite 搜索。
- **笔记：** `/notes/<id>.md`，Markdown 格式。需要多人同时编辑的笔记，正文用 Loro 文本，导出时写成 Markdown。层级用父节点字段表示。
- **待办：** 每个待办一个文件；顺序用分数索引；“完成了多少个” 不保存，而是由文件计算出来。
- **聊天：** 每个会话一个目录，每条消息一个文件；每个人读到哪里，是他自己的一个小文件；“正在输入” 是一条短消息。

## SDK 提供的帮助

`fos-app` SDK 要提供这些，免得每个 App 都重新实现一遍：按 ID 存取记录（生成新 ID、带 schema 版本、保留不认识的字段）、分数索引、Loro 文档，以及一个让缓存文件里的 SQLite 索引和文件保持同步的辅助工具。
