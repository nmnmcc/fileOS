# homeserver

[English](README.md) | **简体中文**

> 一台属于你自己的个人服务器，存放你保存和分享的数据。

homeserver 是一个程序（`hs`），覆盖人们通常要用多个自托管应用拼起来的功能：照片备份、文件同步、聊天、密码、笔记、日历。它按人、时间、地点和事情组织这些数据，不需要服务器运维，并与你认识的人的 homeserver 直接相连。

> [!NOTE]
> **当前状态：实验阶段。** 0.1.0 是一个最小可用版本，完整跑通了核心设计，详见[更新日志](CHANGELOG.md)。数据格式仍可能变化，请保留导出。欢迎反馈和讨论。

---

## 为什么

云服务提供同步、分享和随处访问，但数据由它们保管。照片、聊天、文件、日程和密码通常分散在不同公司，每一家都可能涨价、关停、修改条款或关闭你的账号。

自托管是另一种选择：用 Immich 管照片，用 Vaultwarden 管密码，用 Matrix 聊天。但目前这需要工程能力：许多容器和账号，互不相通的数据，以及持续的升级和排障。

AI 助手让这件事更重要。有用的助手需要了解你的人际关系、去过的地方和手头的工作。这些上下文是私密的，应当留在你自己控制的机器上。

**homeserver 是一台属于你的服务器：不要求你懂它，保管你的数据，只为你工作。**

|      | 云服务             | homeserver             |
| ---- | ------------------ | ---------------------- |
| 计算 | 平台的             | **自己的**             |
| 数据 | 随处可用，平台持有 | **随处可用，自己持有** |
| 身份 | 平台可以关闭的账号 | **自己的密钥**         |
| 关系 | 分散在各个平台     | **人与人直接相连**     |
| 运维 | 平台负责           | **自动完成，无需管理** |

## homeserver 是什么

以下描述的是设计目标，已实现的部分见[更新日志](CHANGELOG.md)。

- **围绕生活组织，而不是围绕应用。** 一个人的页面列出和 TA 有关的聊天、合照、文件和日程；某一天、某个地点或某件事情的页面列出属于它的一切。文件、相册、聊天只是实现细节。
- **是一台设备，不是一个服务。** 一个程序加一个数据目录，不依赖外部组件。证书和 NAT 穿透自动处理，不需要公网 IP。自动升级，失败时自动回滚。任何操作都不需要 SSH。
- **可以长期使用、随时带走。** 身份是你自己的密钥，域名只是别名。换服务器时，联系人和群组随之迁移。任何时候都能以开放格式完整导出。
- **人与人之间的联邦。** 你的 homeserver 与朋友的 homeserver 直接通信。相册、文件夹和文档可以跨服务器分享，实时更新，随时收回。端到端加密。
- **互助。** 每台 homeserver 保存你的数据，也可以为你信任的人充当中继、信箱和加密备份。不使用区块链或代币。
- **个人 AI 的数据所在。** 你的记忆、偏好和关系留在自己的 homeserver 上。你授权的助手只能通过 MCP 等标准接口获取你允许的上下文。默认使用本地模型，哪些数据可以离开由你决定。
- **兼容现有客户端。** 支持 WebDAV、CalDAV/CardDAV、Bitwarden API 等标准协议，可以继续使用你熟悉的客户端。
- **通用需求内置，专业需求靠插件。** 核心只覆盖约 80% 的人日常会用到的功能。影音媒体库、智能家居、代码托管等需求通过插件接入。插件在沙箱中运行，只能访问你授权的数据，并使用 homeserver 身份登录。
- **你的身份提供方。** homeserver 是你和家人的身份提供方，支持 OpenID Connect 等标准协议。插件应用和其他支持标准登录的服务使用同一个身份，授权在一处管理，不需要另外维护认证网关。

## 为什么只有联邦还不够

Matrix 和 Mastodon 是联邦的，但大多数用户集中在少数大服务器上。对多数人来说，联邦意味着选一台别人的服务器。单人服务器可以运行，但处于劣势，自己运行服务器的人很少。

我们认为原因如下，homeserver 逐条应对：

| 人们为什么最后用了大服务器                                                                       | homeserver 的做法                                                                            |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 运行服务器需要域名、公网 IP、证书、数据库和长期维护                                              | 是一台设备：不需要公网 IP 和域名，自动升级，无需管理                                         |
| 身份绑定服务器域名（`@alice:matrix.org`、`@alice@mastodon.social`），离开就要从头开始            | 身份是你自己的密钥，服务器只是托管它的地方。联系人、群组和历史随你迁移                       |
| 成本随整个网络增长：小服务器加入大房间要复制并解析整个房间的状态；关注的人越多，要抓取的媒体越多 | 成本随你自己的数据和关系增长。每个群组有一台主服务器负责事件排序，其他人订阅，而不是复制一切 |
| 小服务器的本地时间线是空的，搜索和发现能力弱                                                     | 关系是人与人直接建立的。通过人认识人，不依赖服务器的公共时间线                               |
| 审核和反垃圾由各服务器管理员负责，小服务器更容易被屏蔽                                           | 规则属于每个人，基于人与人之间的信任，不需要专职管理员                                       |
| 客户端默认把你注册到公共大服务器                                                                 | 默认且最容易的路径是使用自己的 homeserver                                                    |

**衡量成功的标准是有多少人和家庭运行自己的 homeserver，而不是账号数量。**

## 原则

我们提供机制和合理的默认值。**规则由你决定，我们不替任何人做决定。**

按优先级排列。两条原则冲突时，编号小的优先。

| #   | 原则       | 概要                                             |
| --- | ---------- | ------------------------------------------------ |
| 01  | 只属于你   | 数据、身份和关系归你所有，任何时候都可以完整带走 |
| 02  | 以人为中心 | 按人、时间、地点、事情组织，不按数据类型或应用   |
| 03  | 零运维     | homeserver 是一台设备，不是需要管理的服务        |
| 04  | 长期可用   | 按几十年的使用期设计，包括数字遗产               |
| 05  | 可控       | 你能看到谁可以访问什么，并能收回                 |
| 06  | 记忆归你   | 记忆可以查看、修改和删除，不绑定任何 AI 厂商     |
| 07  | 安静       | 目标是让生活更好，而不是增加屏幕时间             |
| 08  | 人与人相连 | 联邦的单位是人                                   |
| 09  | 个人工具   | 用一句话描述就能生成自己的小工具                 |
| 10  | 开放可替换 | 使用标准协议，不锁定用户                         |
| 11  | 互助       | 按你选择的规则，为信任的人提供中继、信箱和备份   |

### 每个功能都要通过的检验

1. 它是否让用户更清楚这些数据归自己所有？
2. 它是围绕人和生活组织的，而不是围绕数据类型？
3. 不懂技术的家人能否独立使用，出问题时能否自己恢复？
4. 二十年后，这些数据还能完整读出吗？
5. 用户能否看到它访问了哪些数据，并收回授权？
6. 它是否会占用用户更多时间，却没有让生活更好？

第 1–5 题必须回答“是”，第 6 题必须回答“否”。未通过的功能延后。

## homeserver 不做什么

| 不做         | 原因                                                               |
| ------------ | ------------------------------------------------------------------ |
| 内置专业功能 | 影音媒体库、智能家居、代码托管等通过插件接入，核心只覆盖日常需求。 |
| 企业功能     | LDAP、审计、合规、组织架构。homeserver 服务的是个人和家庭。        |
| 自建邮件投递 | 保证送达率需要持续投入，超出项目范围。最多支持接收和转发。         |
| 自研 AI 模型 | 对接本地或云端模型，我们只做记忆和授权这一层。                     |
| 通用容器平台 | homeserver 不是 Portainer，也不是应用商店。                        |
| 区块链与代币 | 互助基于关系和信任，而不是报酬。                                   |
| 依赖中心服务 | 可以有官方中继，但任何功能都不能依赖它。                           |

## 设计目标

以下是 v1 的目标，不代表当前版本的能力。

- **1 核 CPU、1GB 内存**可服务 10 人的家庭，空闲内存低于 **150MB**
- **一个程序（`hs`）加一个数据目录**；复制目录即为备份
- 从安装到可用**不超过 5 分钟**，无需配置文件
- **多节点个人集群**（家里的主机、小 VPS、笔记本）共用一个身份，家里断电也不会离线
- 不做全局复制状态：每个群组、相册、文档有一台主服务器负责事件排序，其他服务器订阅
- **单人服务器是一等公民**：没有任何功能在大服务器上比在个人或家庭的 homeserver 上更好用
- 资源占用随你自己的数据和关系增长，与网络规模无关
- 群组加密基于 **MLS（RFC 9420）**

技术路线：使用 Rust，以自包含的单个可执行文件发布，基于 Web 标准构建（一切都有 URL、都使用 HTTP，homeserver 之间也是）。签名的只追加日志和内容寻址的 blob 是事实来源，SQLite 索引由它们派生，随时可以重建。所有节点使用同一套协议，浏览器和手机是你 homeserver 的用户代理。封存的日志和 blob 可以复制到本地目录、另一个 `hs`（你自己的或朋友的）或任何兼容 S3 的存储，因此同步、备份、迁移和联邦是同一个操作，存储只需要 `hs`。网络使用基于 QUIC（quinn 和 rustls）的 HTTP/3 和自己实现的 NAT 穿透，homeserver 之间互相中继。每个共享空间有一条用 MLS 加密的有序事件日志。插件使用 WebAssembly 组件。内置 OpenID Connect 身份提供方。理由和测量数据见[总体架构与技术路线](docs/src/content/docs/zh-cn/dev/architecture.md)。

Rust 编译慢会把没有高性能电脑的贡献者挡在门外，因此我们把编译速度当作一项功能：小 crate、少而精的依赖、不做重型代码生成，并在 CI 中强制执行编译时间预算。一台普通笔记本应当足以参与开发。

## 路线图

暂定。

- [ ] **设计**：宣言与原则、架构白皮书、联邦与互助协议草案
- [ ] **地基**：单一程序、存储、基于密钥的身份、导入工具（Google Takeout、iCloud、聊天记录导出、密码管理器）
- [ ] **生活**：人物页、时间线、地点与事情；文件与照片
- [ ] **相连**：聊天、跨服务器分享、联邦、互助（中继、信箱、加密备份）
- [ ] **记忆**：个人记忆层与助手、MCP 接口
- [ ] **以后**：日历与联系人、协作文档、密码、数字遗产、个人小工具
