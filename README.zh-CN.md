# homeserver

[English](README.md) | **简体中文**

> 你的数字人生，放在你自己的服务器上。

homeserver 是一台属于你自己的个人服务器。它用一个程序（`hs`）取代今天自托管玩家手里那一堆应用（照片备份、文件同步、聊天、密码、笔记、日历），并把它们围绕你的生活组织在一起。它不需要你懂服务器运维，还能让你和在乎的人直接相连。

> [!NOTE]
> **当前状态：设计阶段。** 目前还没有可以运行的代码。本仓库存放的是愿景、原则和设计文档，欢迎反馈和讨论。

---

## 为什么

云来了。它带来了同步、分享和随时随地，代价是我们把生活交了出去。照片在一家公司，聊天在另一家，文件、日程、密码又各在别处。每一家都可以涨价、关停、改规则、封号，每一家都在研究怎样让你多停留一分钟。

自托管证明了另一条路走得通。人们用 Immich 找回照片，用 Vaultwarden 找回密码，用 Matrix 找回对话。但这条路今天只属于少数工程师：几十个容器、几十个账号、互不相通的数据，还有永远做不完的升级和排障。

AI 让这件事变得紧迫。真正有用的助手需要了解你的全部：你和谁亲近，你去过哪里，你在忙什么。这些上下文太私密，不该交给任何平台。它们应该住在你自己的家里。

**所以我们要做 homeserver。它是一台属于你的服务器，不需要你懂它，替你保管数字人生，只为你一个人工作。**

|      | 云时代               | homeserver               |
| ---- | -------------------- | ------------------------ |
| 计算 | 平台的               | **自己的**               |
| 数据 | 随处可用，属于平台   | **随处可用，属于自己**   |
| 身份 | 平台账号，随时可被封 | **自己的密钥，终身可用** |
| 关系 | 困在平台里           | **人与人直接相连**       |
| 运维 | 平台负责             | **不需要懂服务器**       |

## homeserver 是什么

- **围绕生活组织，而不是围绕应用。** 打开一个人，就能看到和 TA 有关的所有聊天、合照、文件和日程；打开某一天、某个地点、某件事情，就能看到属于它的一切。文件、相册、聊天只是实现细节。
- **是一台设备，不是一个服务。** 一个程序加一个数据目录，不依赖任何外部组件。自动申请证书、自动穿透 NAT，没有公网 IP 也能用。自动升级，失败时自动回滚。任何操作都不需要 SSH。
- **陪你一辈子。** 身份基于你自己的密钥，域名只是别名。换服务器时，联系人和群组跟着你走。任何时候都能用开放格式完整导出。
- **人与人之间的联邦。** 你的 homeserver 和朋友的 homeserver 直接对话。跨服务器分享相册、文件夹和文档，实时更新，随时可以收回。端到端加密。
- **邻里互助。** 每台 homeserver 既是你数据的家，也是信任之人的中继、信箱和加密备份。不用区块链，不发代币，就是人与人之间普通的有来有往。
- **个人 AI 的家。** 你的记忆、偏好和关系都留在自己的 homeserver 上。你授权的助手只能通过 MCP 等标准接口拿到你允许的那部分上下文。默认使用本地模型，哪些数据可以出门由你决定。
- **兼容你已经在用的工具。** 支持 WebDAV、CalDAV/CardDAV、Bitwarden API 等标准协议，你可以继续用熟悉的客户端。
- **通用需求内置，专业需求靠插件。** 核心只做 80% 的人日常都会用到的功能。影音媒体库、智能家居、代码托管等专业需求通过插件接入。插件在沙箱中运行，只能访问你授权的数据，并直接使用 homeserver 的身份登录。
- **你的个人认证中心。** homeserver 也是你和家人的身份提供方，支持 OpenID Connect 等标准登录协议。插件接入的应用、其他支持标准登录的服务，都用同一个身份登录，用同一处管理授权。不用再到处维护认证网关。

## 为什么只有联邦还不够

Matrix 和 Mastodon 都是联邦的，但大多数人仍然聚集在少数几个大服务器上。对大多数用户来说，联邦只意味着"选一台别人的服务器"。一个人的服务器在它们那里也能运行，但处处吃亏。每个人拥有自己服务器的局面从来没有出现。

我们认为原因有以下几条。homeserver 针对每一条来设计：

| 人们为什么最后都去了大服务器                                                                     | homeserver 怎么做                                                                      |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 自己运行服务器需要域名、公网 IP、证书、数据库，还要长期维护                                      | 是一台设备：不需要公网 IP 和域名，自动升级，没有需要管理的东西                         |
| 身份绑定在服务器域名上（`@alice:matrix.org`、`@alice@mastodon.social`），离开就等于从头开始      | 身份是你自己的密钥，服务器只是它住的地方。换服务器时，联系人、群组和历史都跟着你走     |
| 成本随整个网络增长：小服务器加入大房间要复制并解析整个房间的状态；关注的人越多，要抓取的媒体越多 | 成本随你自己的生活增长。每个群组有一台主服务器负责排序，其他人订阅，而不是人人复制一切 |
| 小服务器很冷清：本地时间线是空的，搜索和发现都很弱                                               | 关系是人与人直接相连的。通过人认识人，不依赖服务器上的公共时间线                       |
| 审核和反垃圾是每台服务器管理员的活，小服务器还更容易被屏蔽                                       | 规则属于每个人，建立在信任关系之上，不需要专职的服务器管理员                           |
| 客户端默认把你注册到一台公共大服务器上                                                           | 默认的路径就是拥有自己的 homeserver，而且这是最容易的那条路                            |

**我们衡量成功的标准，是有多少人和家庭运行着自己的 homeserver，而不是有多少账号。**

## 原则

我们提供机制和合理的默认值，**规则由你决定。我们不替任何人做决定。**

原则按优先级排列。两条原则冲突时，编号小的优先。

| #   | 原则           | 一句话                                           |
| --- | -------------- | ------------------------------------------------ |
| 01  | 只属于你       | 数据、身份、关系归你所有，任何时候都可以完整带走 |
| 02  | 以人为中心     | 按人、时间、地点、事情组织，不按数据类型和应用   |
| 03  | 零运维         | homeserver 是一台设备，不是需要管理的服务        |
| 04  | 陪你一辈子     | 按几十年来设计，包括数字遗产                     |
| 05  | 掌控感         | 随时知道谁能看到什么，并且可以收回               |
| 06  | 它记得你       | 记忆归你，可查看、修改、删除，不绑定任何 AI 厂商 |
| 07  | 安静           | 目标是让你过得更好，不是让你多用一会儿           |
| 08  | 人与人直接相连 | 联邦的单位是人                                   |
| 09  | 长成你的样子   | 一句话生成只属于你的小工具                       |
| 10  | 开放与可替换   | 标准协议，不靠封闭留住用户                       |
| 11  | 互助           | 按你选择的规则，为信任的人提供中继、信箱和备份   |

### 每个功能都要过的检验

1. 它让用户更觉得“这是我的”吗？
2. 它是围绕人和生活组织的，还是围绕数据类型？
3. 一个不懂技术的家人，能不能不求助就用起来、出了问题能不能自己恢复？
4. 二十年后，这份数据还能完整读出来吗？
5. 用户能看清它碰了哪些数据，并且能收回吗？
6. 它会不会让用户多花时间，却没有让生活变好？

前五个问题必须回答“是”，最后一个必须回答“不会”。答不上来的功能，往后放。

## homeserver 不做什么

| 不做           | 原因                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------- |
| 内置专业功能   | 影音媒体库、智能家居、代码托管等不进核心，通过插件接入。核心专注于 80% 的人日常都会用到的通用需求。 |
| 企业功能       | LDAP、审计、合规、组织架构。homeserver 服务的是一个人和家人。                                       |
| 自建邮件投递   | 送达率是无底洞。最多接收和转发。                                                                    |
| 自研大模型     | 对接本地或云端模型，我们只做记忆和授权这一层。                                                      |
| 通用容器平台   | homeserver 不是又一个 Portainer，也不是应用商店。                                                   |
| 区块链与代币   | 互助靠关系和信任维系，不靠金钱激励。                                                                |
| 依赖中心的服务 | 官方中继可以有，但任何功能都不能离开它就无法工作。                                                  |

## 设计目标

以下是 v1 的目标，不代表现有软件的能力。

- **1 核 CPU、1GB 内存**即可流畅服务 10 人的家庭，空闲内存低于 **150MB**
- **一个程序（`hs`）加一个数据目录**：复制目录就是备份
- 从安装到可用**不超过 5 分钟**，无需配置文件
- **多节点个人集群**（家里的小主机 + 小 VPS + 笔记本）共用一个身份，家里断电也不会掉线
- 不做全局复制状态：每个群组、相册、文档都有一台主服务器负责事件排序，其他服务器订阅
- **一个人的服务器是一等公民**：没有任何功能在大服务器上比在一个人或一个家庭的 homeserver 上更好用
- 资源占用随你自己的数据和关系增长，与整个网络的规模无关
- 群组加密基于 **MLS（RFC 9420）**

技术路线：Rust，以内含一切的单个可执行文件发布，深度基于 Web 的思想和标准（一切都有 URL、都说 HTTP，homeserver 之间也是）；签名的只追加日志和内容寻址的 blob 是事实，SQLite 索引由它们派生，随时可以重建；处处是同一套协议，浏览器和手机是你 homeserver 的用户代理；封存的日志和 blob 可以复制到本地目录、另一个 `hs`（你自己的或朋友的）或任何兼容 S3 的云存储，同步、备份、迁移和联邦是同一个操作，存储只需要 `hs`；QUIC（quinn 和 rustls）上的 HTTP/3，加我们自己的 NAT 穿透，homeserver 之间互相中继；每个共享空间一条有序的事件日志，用 MLS 加密；插件使用 WebAssembly 组件；内置 OpenID Connect 身份提供方。理由和测量数据见[总体架构与技术路线](docs/src/content/docs/zh-cn/architecture.md)。

Rust 的编译可能很慢，这会把没有高性能电脑的人挡在门外。我们把编译速度当作一项功能来对待：小而清晰的 crate、少而精的依赖、不做重型代码生成，并在 CI 中强制执行编译时间预算。一台普通笔记本就应该足以参与开发。

## 路线图

暂定，可能调整。

- [ ] **设计**：宣言与原则、架构白皮书、联邦与互助协议草案
- [ ] **地基**：单一程序、存储、基于密钥的身份、导入工具（Google Takeout、iCloud、聊天记录导出、密码管理器）
- [ ] **生活**：人物页、生活时间线、地点与事情；文件与照片
- [ ] **相连**：聊天、跨服务器分享、联邦、互助（中继、信箱、加密备份）
- [ ] **记忆**：个人记忆层与助手、MCP 接口
- [ ] **以后**：日历与联系人、协作文档、密码、数字遗产、个人小工具
